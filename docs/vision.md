# NoCloud — к чему идём

Документ опирается на:

- текущий задел репозитория (`docs/plan.md`, `docs/features-realtime.md`, код);
- согласованные решения в [requirements.md](./requirements.md) и суть идей в [sources/ideas-essence.md](./sources/ideas-essence.md).

Это **целевая картина продукта**, шире v1 «обмен файлами». Старый `plan.md` остаётся планом уже сделанного/делаемого фундамента WebRTC+файлы.

---

## 1. Продукт одной фразой

**Суверенная P2P-звонилка и обмен** (голос, видео, файлы, позже сообщения): личность — ваши ключи, серверы — сменные реле, медиа — напрямую по WebRTC, без обязательного облака и без аккаунта у нас.

---

## 2. Принципы (не компромисс по умолчанию)

1. **Автономная идентичность.** Аккаунт создаётся офлайн, как кошелёк: приватный ключ локально, публичный — глобальный ID. Никто не «выдаёт» свободный ник как первичный ID.
2. **Сервер не владеет человеком.** Релей — временный «дом». Смена реле не меняет личность.
3. **Клиент умный, сервер тупой.** Поиск пути, пучки узлов, выбор STUN/TURN, восстановление после блокировок — на клиенте.
4. **Три уровня знакомства живут вместе.** Прямой обмен (QR/NFC/LAN) · локальная сеть · интернет через свои/чужие реле + DHT.
5. **Локальная книга сильнее глобального ника.** Фишинг «ещё один Лёша» не перетирает ваш alias.
6. **Файлы и медиа не лежат у нас.** Signaling видит SDP/кандидаты; TURN — только явный/свой; сообщения — E2EE.
7. **PWA + десктоп-нода.** Браузер — лёгкий клиент; установленное приложение на ПК может стать полноценным узлом сети для себя и друзей.

## 3. Слои целевой системы

```
┌─────────────────────────────────────────────────────────┐
│ UI (PWA / Tauri)  звонки · контакты · файлы · чат · серверы │
├─────────────────────────────────────────────────────────┤
│ Session / Call / Transfer / Presence                      │
├─────────────────────────────────────────────────────────┤
│ Identity (ключи) · Profile (подпись) · Address book       │
├─────────────────────────────────────────────────────────┤
│ Signaling router · Peer discovery · Optional DHT          │
├─────────────────────────────────────────────────────────┤
│ WebRTC (media + data) · ICE (STUN/TURN из пучка)          │
├─────────────────────────────────────────────────────────┤
│ Local store (OPFS / IndexedDB / desktop FS) · E2EE        │
└─────────────────────────────────────────────────────────┘
         ▲                         ▲
   bootstrap / relays        desktop node (опц.)
```

## 4. Что уже есть (задел)

| область | сейчас |
|---|---|
| PWA оболочка, Vite+, слои config/domain/lib | да |
| WebRTC DataChannel, файлы/папки, resume | да |
| Signaling (manual / HTTP poll / WS), STUN, свой TURN deploy | да |
| Профиль: короткий `id`, nick, avatar; карточка `C1.` | да (не крипто-ключи) |
| Контакты, группы, presence-лобби `c-{id}`, стук | да |
| Экраны «Звонки» (голос/видео/экран) как UI-задел | частично (треки — дальше) |
| Десктоп-нода, DHT, E2EE-чат, PoW, мульти-релей роутинг | нет |

Задел = транспорт и UX знакомства. Цель диалога = **личность + сеть реле + звонилка + устойчивость**.

## 5. Целевые пользовательские сценарии

1. **Создать себя офлайн** → ключи + профиль → QR «это я».
2. **Позвонить** контакту из книги: клиент сам выбирает реле/прямой путь/TURN.
3. **Сменить сервер** → друзья находят через DHT / редирект / новую встречу QR.
4. **Переслать контакт** → получатель сам подтягивает актуальный профиль по pubkey.
5. **Локально переименовать** → глобальный ник не меняется.
6. **Файл/папка** — как сейчас, но в сессии того же identity/call stack.
7. **Опционально**: синк истории между своими устройствами (P2P или зашифрованный бэкап на реле).
8. **Десктоп дома** поднимает ноду → телефон-PWA цепляется к ней как к своему реле.

---

## 6. Сознательные границы (пока)

- Не строим коммерческий BaaS-аккаунт (Firebase/Clerk).
- Не обещаем системный Nearby/Wi‑Fi Direct в чистом PWA (только то, что даёт браузер + десктоп позже).
- Не делаем «ещё один Matrix с доменами как ID».
- Не кладём чужой открытый TURN по умолчанию.
- Полный DHT в браузере — поэтапно; сначала пучок реле + прямой обмен, DHT усиливает.

---

## 7. Критерий «мы туда пришли»

Два телефона (PWA) и опционально один ПК-нода:

- личности созданы офлайн и стабильны;
- звонок и файл идут P2P после знакомства через реле или QR;
- смена реле у одного не «убивает» личность; есть способ снова найтись;
- контакт можно переименовать локально и переслать третьему;
- без нашего облака продукт остаётся рабочим при живых реле пользователей.
