# Глоссарий NoCloud

Короткие русские определения терминов проекта. Для новых участников — читать вместе с [architecture.md](./architecture.md).

## Клиент и поставка

| термин | что это |
|---|---|
| **PWA** (Progressive Web App) | Веб-приложение, которое ставится на телефон/ПК как «приложение»: иконка, офлайн-оболочка, свой origin. Это **клиент**, не сервер. |
| **WebView** | Встроенный браузер внутри нативной оболочки (Android/iOS/desktop). Тот же фронт, что PWA, можно упаковать в apk/ipa без переписывания доменов. Сторы часто принимают так, чистый PWA — реже. |
| **UI / shell** | Экранная оболочка (ориентир Telegram): списки, звонок, настройки. Не содержит крипто и SDP. |
| **MVP / M1** | Первый проверяемый срез: identity + QR-контакты + голос 1:1 + файлы + грубый Telegram-UI. |

## Идентичность и крипто

| термин | что это |
|---|---|
| **Identity** | Личность пользователя: пара ключей, создаётся офлайн. |
| **Приватный ключ** | Секрет на устройстве. Им подписывают профиль и ответы реле. Никогда не на сервер (кроме зашифрованного бэкапа по желанию пользователя). |
| **Публичный ключ (pubkey)** | Открытая часть. По ней вас узнают в сети. |
| **Fingerprint** | Короткий отпечаток pubkey для UI (удобнее показывать человеку). |
| **Ed25519** | Алгоритм подписи (выбран для MVP). Реализация через `@noble/ed25519`, сменный порт. |
| **Подпись / verify** | Доказательство, что данные от владельца ключа; чужая подпись отбрасывается. |
| **BIP39 / seed-фраза** | Набор слов для восстановления личности. |
| **Master-фраза** | Фраза при регистрации: шифрует локальный ключ и бэкап; может совпадать со seed. |
| **Биометрия (unlock)** | Face ID / отпечаток как удобный вход на устройстве, **не** замена фразе для восстановления. |

## Сеть и WebRTC

| термин | что это |
|---|---|
| **P2P** (peer-to-peer) | Прямой канал между устройствами. Файлы и медиа после знакомства идут так, без нашего облака. |
| **WebRTC** | Браузерный стек для P2P: голос, видео, DataChannel. |
| **PeerConnection (PC)** | Один WebRTC-сеанс между двумя сторонами. У нас: один PC на data + media. |
| **DataChannel** | Канал байтов/JSON внутри PC (файлы, служебные сообщения). |
| **SDP** | Техническое «резюме» соединения (codecs, кандидаты). Обмениваются при старте. |
| **ICE** | Перебор путей связи: прямые адреса → через STUN → через TURN. |
| **кандидат host / srflx / relay** | Типы найденных адресов: локальный / «отражённый» через STUN / через TURN. |
| **STUN** | Сервер, который говорит клиенту его внешний IP:порт. Сам медиа не тащит. |
| **TURN** | Релей **медиа/байтов**, если прямой P2P не вышел. Видит трафик → только свой/явно выбранный. |
| **NAT** | Роутер/оператор прячет устройство за общим адресом; часто ломает «голый» P2P. |
| **Signaling** | Обмен SDP/ICE **до** P2P. Маленькие служебные сообщения, не файлы звонка. |
| **WebSocket (WS)** | Типичный транспорт signaling по TCP. |
| **WebTransport / HTTP/3 / QUIC** | Современные транспорты; пробуем как **адаптер** signaling рядом с WS, где уместно. |

## Реле и отказоустойчивость

| термин | что это |
|---|---|
| **Реле / relay-узел** | Сервер знакомства и presence. **Не** хранит ваши файлы и не обязан видеть голос. |
| **Node (тонкий Node.js)** | В этом проекте: реализация реле в `server/` на Node.js. **Это не PWA.** Позже язык ноды можно сменить, контракт сохранить. |
| **Bootstrap / seed** | Стартовые адреса реле, с которых клиент узнаёт другие живые узлы. |
| **Пучок реле** | Кэш многих адресов; клиент держит до нескольких активных (задел на блокировки). |
| **Signed challenge** | Реле шлёт случайное число → клиент подписывает ключом → реле пускает. Auth без пароля. |
| **Rate-limit** | Ограничение частоты запросов с pubkey/IP против спама. |
| **PoW** (Proof of Work) | Клиент решает мелкую «загадку» перед тяжёлым запросом; усложняет массовый спам. Сейчас задел в интерфейсе, не обязателен в MVP. |
| **Redirect / записка** | Подписанное «я переехал на другие реле» на старом узле. |
| **DHT** | Распределённая «телефонная книга» между узлами (later). |

## Звонки и группы

| термин | что это |
|---|---|
| **Call / звонок** | Логическая сессия; внутри — набор **ног (legs)** к участникам. |
| **Leg** | Связь с одним пиром (один PC). |
| **Mesh** | Каждый с каждым напрямую. Комфортно примерно до 4–6 участников. |
| **SFU** | Selective Forwarding Unit: медиа-узел принимает потоки и раздаёт. Нужен на 7–20+. Видит медиа, если нет доп. E2EE. |
| **Топология (strategy)** | Выбор mesh vs SFU; закладываем интерфейс сразу, в MVP — 1:1 mesh. |
| **Presence** | Признак «контакт сейчас доступен» через реле. |
| **Knock / стук** | Запрос «открой сессию» к онлайн-контакту. |
| **Комната (служебная)** | Внутренний id для signaling. Пользователь в 1:1 комнатами не управляет — есть контакты. |

## Файлы и хранение

| термин | что это |
|---|---|
| **Transfer** | Передача файла/папки по DataChannel. |
| **OPFS** | Приватное файловое хранилище origin в браузере (inbox и т.д.). |
| **IndexedDB** | Локальная БД браузера (ключи в зашифрованном виде, настройки). |

## Организация кода

| термин | что это |
|---|---|
| **Домен / модуль** | Область ответственности (identity, call, relay…), без циклов зависимостей. |
| **Адаптер** | Обёртка над транспортом (WS, WebTransport, manual QR) с одним контрактом. |
| **ADR** | Architecture Decision Record — короткая запись «почему так решили». |
| **Control plane** | Сигналинг/presence/роутинг ног. |
| **Media plane** | Голос/видео/файлы (P2P или TURN/SFU). |

## Частые путаницы

| путают | на самом деле |
|---|---|
| Node = PWA | Нет. **Node** = реле-сервер; **PWA** = клиент в браузере. |
| Реле = облако файлов | Нет. Реле не хранит содержимое передач. |
| STUN = TURN | STUN только «узнай свой адрес»; TURN — тащит байты. |
| Комната = чат-группа | В MVP комната служебная; группа (чат/звонок на N) — later. |
| Биометрия = бэкап | Нет. Бэкап — фраза/файл; биометрия только unlock на устройстве. |
