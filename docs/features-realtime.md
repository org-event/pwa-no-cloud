## Модель комнат

- У каждого человека **лобби**: `c-{profileId}` (см. `meetRoomId`).
- Пока вы **доступны**, клиент держит signaling-сокет в своём лобби → другие видят ваш id в `peers`.
- **Стук / звонок / файлы**: отдельная PeerSession заходит в лобби собеседника (или принимает гостя в своём). Presence-сокет при этом остаётся — вы не «пропадете» из сети.
- Клиенты с id `watch:…` — только разведка presence, WebRTC их игнорирует.

## Почему не «все комнаты сразу»

Один PeerSession = один call. Presence — отдельный лёгкий сокет на своё лобби + короткие probe в чужие. Так можно видеть ABCD онлайн и стучаться к одному, не держа 4 WebRTC.

## После сна телефона

1. Wake Lock снижает засыпание экрана, пока вкладка видима и вы «доступны».
2. По `visibilitychange` / online снова поднимаем лобби и опрос.
3. Чужие узнают, что вы онлайн, когда ваш id снова появляется в `c-{вы}` — не через push «я проснулся», а через membership в лобби.
