# Свой TURN для режима через интернет

NoCloud не кладёт чужой открытый TURN в пресеты.
Публичный STUN Google допустим: он только помогает узнать внешний адрес.
TURN видит байты DataChannel, поэтому релей — только ваш или явно введённый.

Если устройства в разных сетях и ICE пишет «прямой путь закрыт NAT» —
нужен свой TURN. Пока его нет, пресет оставляйте пустым и соединяйтесь
вручную или в одной LAN.

## Что вписать в «Свой сервер»

1. Пресет **Свой сервер**.
2. Signaling — ваш WebSocket/HTTP, если знакомство не вручную.
3. STUN — свой или `stun:stun.l.google.com:19302`.
4. TURN URL, логин и пароль. Примеры:

```
turn:turn.example.com:3478
turns:turn.example.com:5349
```

Без логина и пароля конфиг не сохранится.
Секреты живут только в `localStorage` браузера, не в репозитории.

Если канал открылся через релей, в приглашении будет
`сейчас путь = relay`.

## coturn (черновик)

Минимум на своей машине или VPS. Подставьте домен, логин и пароль сами.

```bash
docker run --rm -p 3478:3478 -p 3478:3478/udp -p 5349:5349 \
  -e DETECT_EXTERNAL_IP=yes \
  coturn/coturn \
  -n --log-file=stdout \
  --fingerprint --lt-cred-mech \
  --user=USER:PASSWORD \
  --realm=turn.example.com
```

Для продакшена обычно нужны:

- белый IP или порт-форвардинг;
- `--external-ip` если контейнер за NAT;
- `turns:` и сертификат на 5349, если нужен TLS;
- файрвол: UDP/TCP 3478, плюс диапазон релея, если задаёте `--min-port` / `--max-port`.

Проверка: после сохранения пресета два телефона в разных сетях.
Успех — канал открыт, путь `host`, `srflx` или `relay`.
Fail без TURN — текст про NAT, не «просто ошибка».
