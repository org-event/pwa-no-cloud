# Свой TURN для режима через интернет

NoCloud не кладёт чужой открытый TURN в пресеты.
Публичный STUN Google допустим: он только помогает узнать внешний адрес.
TURN видит байты DataChannel, поэтому релей — только ваш или явно введённый.

Если устройства в разных сетях и ICE пишет «прямой путь закрыт NAT» —
нужен TURN. Пока своего нет, для проверки канала можно временно вписать
бесплатный Open Relay (ниже). В пресеты репозитория чужой TURN не кладём.

## Что вписать в «Свой сервер»

В приложении **Мой сервер**: SSH-логин и IP. Две команды:

```bash
ssh root@YOUR.IP
curl -fsSL https://raw.githubusercontent.com/org-event/pwa-no-cloud/main/deploy/install-turn.sh | sudo bash
```

Скрипт на VPS (как у Amnezia) поставит Docker, если его нет, запустит
службу, если она остановилась. Дальше спросит логин и пароль TURN
(Enter — сгенерировать) и порты. По умолчанию **80 и 443** — их обычно
не режут корпоративные сети. Можно взять ещё 3478 или свой список.

В конце скрипт печатает логин, пароль, порты, строку `S1.` и QR.
Считайте QR в NoCloud → **Мой сервер**, либо вставьте `S1.`.
Если отмечено «Вложить мои серверы», приглашение N1. несёт TURN
второму устройству.

Домен для TURN не нужен: 80/443 слушает coturn по TCP, не HTTPS-сайт.
Сокет для GitHub Pages **нужен с TLS**. Установщик берёт имя
`wss-<IP-с-дефисами>.sslip.io` и выпускает Let’s Encrypt ~90 дней.
TURN слушает **443, 80 и 3478** (TCP и UDP): контейнер от root, иначе
80/443 не открываются. STUN в S1 — те же порты, сначала 443.
Email спрашивает один раз (`/opt/nocloud-turn/acme.env`), cron продлевает
сертификат. На выпуск ACME кратко освобождается TCP 80.
Если в PWA всё ещё `http://…:8443` — это старый пакет: перезапустите
установщик и вставьте новый S1.

Либо вручную те же URL:

```
turn:YOUR.IP:80?transport=tcp
turn:YOUR.IP:443?transport=tcp
```

Без логина и пароля конфиг не сохранится.
Секреты живут только в `localStorage` браузера, не в репозитории.
На сотовой сети одного UDP URL часто мало: в пакете S1. уже есть
TCP на 80 и 443 (их браузер пробует первыми). QR с консоли VPS
сохраняет весь пакет в PWA. Приглашение может вложить эти серверы,
если у второго своих нет.

Если PWA пишет «TURN задан, но relay-кандидат не появился»:
оба устройства должны вставить один и тот же S1. После правки
квоты coturn перезапустите установщик на VPS (`curl | sudo bash`)
и вставьте новый S1. Проверка самого TURN:
https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/
там должен появиться кандидат `relay`.

## Тест: Open Relay (бесплатно, нужна регистрация)

Публичного TURN без учётки в 2026 почти нет: старые `openrelayproject`
и чужие логины из статей отозваны или чужие. Для проверки NoCloud
достаточно бесплатного яруса Metered Open Relay (20 ГБ/мес).

1. Зарегистрируйтесь: https://www.metered.ca/tools/openrelay/
2. В кабинете создайте TURN credential и скопируйте логин, пароль
   и список URL. Либо вызовите их REST API
   `https://<app>.metered.live/api/v1/turn/credentials?apiKey=...`
   и скопируйте JSON.
3. На **каждом** устройстве: пресет **Свой сервер**, signaling **Вручную**.
4. STUN: `stun:stun.l.google.com:19302` (можно оставить Google).
5. TURN: все URL из кабинета, по одному в строке. Если форма ещё старая
   и принимает один URL — берите `turns:...:443?transport=tcp`
   (лучше проходит мобильный NAT и файрвол).
6. Либо вставьте весь `iceServers` JSON в поле «или iceServers JSON».
7. Сохраните. Старое приглашение `N1.` выбросьте: в нём нет relay.
8. Создайте приглашение заново и обменяйтесь ответом.

Проверка самого TURN до NoCloud:
https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/
Там должен появиться кандидат типа `relay`.

Имя комнаты (`Droid`) на ручном приглашении не влияет: комната нужна
только LAN-серверу. Оба конца должны иметь **один и тот же** TURN.

Трафик файла при `сейчас путь = relay` идёт через Metered. Это тест,
не «без облака». Для постоянной работы поднимите свой coturn.

Если канал открылся через релей, в приглашении будет
`сейчас путь = relay`.

## coturn

Готовый установщик: `deploy/install-turn.sh` и образ
`deploy/turn/Dockerfile` (обёртка над `coturn/coturn:4.6.2`).
Секреты в образ не запекаются.

Проверка: Trickle ICE, кандидат `relay`. Два телефона в разных сетях.
Fail без TURN — текст про NAT, не «просто ошибка».
