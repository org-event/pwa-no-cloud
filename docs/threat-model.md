# Threat model — NoCloud (M3)

Дата: 2026-09  
Связано: [NFR-SE-02](./requirements.md), [NFR-SE-04](./requirements.md), [architecture.md](./architecture.md) §6, [adr/0002](./adr/0002-ownership-and-secrets.md).

Цель документа — **честные границы** до маркетинга. Не обещаем
«неубиваемость» и не целимся в DPI-state adversary на текущем срезе.

## 1. Активы

| актив | где | что защищаем |
|---|---|---|
| Identity secret (Ed25519) | устройство (vault / master / BIP39) | подмена личности, кража ключа |
| Адресная книга + `localAlias` / `trust` | OPFS / local | утечка связей и меток доверия |
| История чата `H1.` | локально на устройстве | чтение чужим на том же устройстве / бэкап без шифрования |
| Файлы / медиа | P2P DataChannel / media | реле не должно видеть содержимое |
| Пакеты `S1.` / TURN secrets | настройки пользователя | чужой TURN / утечка creds в git |
| Presence / signaling метаданные | реле | кто с кем и когда стучится |

## 2. Противники (целевые на M1–M3)

| противник | модель | отношение продукта |
|---|---|---|
| Случайный админ / оператор реле | видит метаданные signaling, IP при подключении, может дропать/логировать | **да**, проектируем против |
| Фишинг ника / подмена карточки | чужой `P1.`/`I1.` с похожим ником | **да** (подпись + trust UI) |
| Пассивный наблюдатель сети | видит факт соединения, размеры/тайминг; не plaintext чата/файлов на PC | частично |
| Вредонос на том же устройстве | читает unlocked vault / OPFS | **вне** обещаний (OS trust) |
| DPI / nation-state | блокировки, correlation, принуждение реле | **не** цель M3 |

## 3. Что уже закрываем

1. **Контент не на реле.** Чат (`H1.`), файлы и media идут по WebRTC (DTLS на
   PeerConnection). Реле — знакомство и presence, не хранилище сообщений.
2. **Подпись.** Карточки `P1.`, introduce `I1.`, redirect `R1.`, чат `H1.` —
   Ed25519; приём с verify.
3. **Локальный trust.** `unverified` / `introduced` / `met` не уходят в сеть;
   UI «видели лично» — локальная метка (FR-PR-07).
4. **Ключи.** Offline create; unlock master/BIP39; encrypted backup; OwnedSecret
   lifecycle (ADR 0002). Биометрия — только unlock, не источник секрета.
5. **Чужой TURN.** По умолчанию не подключаем; свой — по [turn.md](./turn.md).
6. **Abuse задел.** Rate-limit + challenge на реле; PoW stub в том же
   интерфейсе (`createNoopAbuseGuard` по умолчанию).

## 4. Что реле / сеть всё ещё видят

- Факт регистрации presence и стука (кто online, room/channel id).
- IP и ICE-кандидаты (STUN/TURN раскрывают топологию).
- Размер и тайминг пакетов signaling; при своём TURN — IP peers.
- `R1.` redirect store: публичный GET по pubkey до TTL (заметка намеренно
  для друзей на старом реле).

Реле **не** должно видеть текст чата и байты файлов при штатном P2P.

## 5. Что не обещаем

- Защиту от DPI, блокировок и активного nation-state.
- Анонимность IP / невозможность связать двух peers по метаданным.
- Safety-number как у Signal (пока — trust-метка + личный обмен QR).
- Sealed multi-device sync истории чата (M3: история локальная).
- Невозможность утечки при компрометации устройства или heap snapshot
  (wipe — best-effort).

## 6. UX-дисклеймер

UI и usage не должны обещать «полный E2EE против всех» или «нас не
заблокировать». Честные формулировки: *напрямую между устройствами*,
*реле не видит содержимое файлов/чата*, *свой TURN при NAT*.
